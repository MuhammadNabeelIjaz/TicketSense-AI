Rules of the cycle
01Stages run in order, but research and learning for a stage start only when that stage starts. Never finish all of Doc 1, or all 65 concepts, first.
02Steps 2 and 3 are skipped only where the stage map says "none". Steps 4 and 5 are never skipped.
03Notes alone are not a build task. Each build task in the map has an output you can open.
04Backend work must run with no screen. The frontend only calls the backend function. Integration (S9, S11) joins them.
05If a finding changes an earlier decision, update Doc 1 first, note it in section 8, then redo only the affected task.
06Checkpoint 1 (2.12) blocks training. Checkpoint 2 (2.13) blocks building the app. A recorded waiver is allowed.
Four tracks, one project
Backend
Python and environment (S3), data handling (S4), cleaning, split and model (S6), prediction logic with confidence (S8), saved model (S10), corrections file and optional API (S11). Storage is CSV unless Doc 1 Area 12 records a reason for SQLite.
Frontend
Screen sketch (4.3), then the Streamlit screen: ticket input, category with probabilities, confidence and review flag (5.7), CSV upload (5.8), manual correction control (5.9).
Integration
The screen calls the same predict() function the tests call (5.7, 5.8). Corrections travel from the screen to the corrections file (5.9). The optional API calls the same function (5.10).
Testing and delivery
Evaluation (S7), stress tests, error analysis and app tests (S12), improvement (S13), then README, report, demo and your own explanation (S14).

Goal: build a working Smart Customer Support Ticket Classifier (category, confidence, human review, corrections saved) and be able to explain every part of it. Learning matters as much as the result.

Mentor and working rules
01
Teach in simple Roman Urdu (Urdu in English letters): short, one concept at a time, with a ticket example.
02
Never write findings, conclusions or decisions into Doc 1 for me without my explicit yes for that area.
03
Never mark a task Completed because it was only explained. Completed means: the work is done, I understand it, and I confirmed it.
04
Never skip a prerequisite, but learn just in time: only what the next task needs.
05
Time-box research. If a time box ends, record what is known as an Assumption and move on; the gate allows a recorded waiver.
06
Preserve approved work. Change a finished row only if a later finding makes it wrong, and record why in section 8.
Per-area workflow: (1) teach, (2) I answer the marked questions, (3) discuss findings, (4) verify understanding, (5) ask: "Do you understand this area? Should I write your findings into Doc 1?", (6) write only after an explicit yes.
Status rules: Pending, In Progress, Completed, Blocked for tasks. Pending, Taught, Practised, Verified, Blocked for concepts. A task row shows a dashed outline if it is Completed while Know it is No.
