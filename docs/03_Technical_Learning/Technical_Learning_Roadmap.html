How this roadmap works

A reference list of the technical concepts you need, in prerequisite order. It teaches nothing by itself and records no progress: lessons happen one concept at a time, and status is recorded only in the Tracker (Doc 3, section 5, Phase 3).
1. Levels
LevelMeaningRule
EssentialNeeded for the Minimum Path (the 7 to 14 day project)Learn just in time: when the next project step needs it
UsefulUnderstand the idea; building it is optionalFull Track, or after the Essentials of that unit
AdvancedOnly after the core project worksNever delays the project
2. How to learn an Essential concept (Minimum Path)
01
Teach: a 15 to 20 minute explanation in simple Roman Urdu with one ticket example.
02
Use: apply it in the real project step shown under "Minimum Path practice" on each unit page. Do not build separate toy exercises unless you are on the Full Track.
03
Check: answer the unit's "How to verify" question in your own words, two lines in the daily log.
04
Record: set the status in the Tracker (Pending, Taught, Practised, Verified) and write the evidence (file, output or log date).
3. Rules
01
Understanding first, practical work second. One concept at a time; do not move on while the current one is unclear.
02
A concept is Verified only after you used it and answered its check in your own words.
03
Concepts marked added in the change log were not in your first list but are needed to build and explain the project (E6 Pipeline, H11 pytest).
04
This document holds no status. Never record progress here; use the Tracker.

BUnit B: Machine learning fundamentals6 ESSENTIAL · 0 OTHER

You will be able to: You can describe, in plain words, how a model learns categories from labelled tickets and why it can fail on new ones.

IDConcept and what it meansLevelLearn firstWhere used in TicketSense-AI
B1What is machine learningA program that learns patterns from examples instead of fixed rules.EssentialA5The whole project idea
B2Supervised vs unsupervised learningSupervised learning uses labelled examples; unsupervised finds groups without labels.EssentialB1Your data has labels, so it is supervised
B3Classification vs regressionClassification predicts a category; regression predicts a number.EssentialB2Category = classification
B4Training, testing and inferenceTraining learns from past tickets, testing checks unseen ones, inference predicts new ones.EssentialB2, A5Fit on past tickets, predict new ones
B5Overfitting, underfitting and generalizationOverfitting memorizes training data; underfitting learns too little; generalization works on new data.EssentialB4Why test accuracy matters more than training accuracy
B6Reproducibility basicsFixing random seeds and noting the Python version, library versions and data version so a run can be repeated.EssentialB4Same split and scores on every run; others can rerun your project
Learn first
Features and labels (A5).
Why it matters
Every model choice and every metric later rests on these ideas.
Minimum Path practice (the real project step)
Write three lines in your daily log: why TicketSense-AI is supervised classification, and why test accuracy matters more than training accuracy. Fix the random seed and note library versions (5.1, 5.3).
Expected output
Three lines in the daily log and a seed set in your split code.
How to verify
Explain why a model that scores 100% on its training tickets may still fail on new tickets, using one example message.
Optional warm-up on invented data (Full Track only)
Sort five example problems (spam filter, house price, grouping customers, and so on) into supervised/unsupervised and classification/regression, then mark where TicketSense-AI sits.

CUnit C: NLP fundamentals3 ESSENTIAL · 2 OTHER

You will be able to: You can turn a raw customer message into clean, consistent tokens and explain each cleaning choice.

IDConcept and what it meansLevelLearn firstWhere used in TicketSense-AI
C1Text processing, cleaning and normalizationMaking text consistent: lowercase, punctuation, spacing, noise.EssentialA4, B4Cleaning ticket text before vectorizing
C2TokenizationSplitting text into small units, usually words.EssentialC1Splitting a message into words
C3Stop wordsVery common words (the, is) sometimes removed; the lists have known limits.UsefulC2Deciding whether to drop words like "the"
C4Stemming and lemmatizationReducing words to a base form (charging becomes charge).UsefulC2Treating "charged" and "charging" alike, if helpful
C5Vocabulary and n-gramsVocabulary is the set of known words; n-grams are word sequences such as "refund request".EssentialC2Word pairs such as "refund request"
Learn first
Python strings and lists (A1), Pandas columns (A4).
Why it matters
The model only sees what your preprocessing leaves; cleaning choices change results, so you must be able to justify them.
Minimum Path practice (the real project step)
Write a short cleaning function and show five real messages before and after it (5.3). Keep it light: lowercase, trim spaces, keep words such as "not".
Expected output
A before and after table of five messages from your dataset.
How to verify
Give one example where removing stop words helps and one where it could hurt (for instance "not" in "not working").
Optional warm-up on invented data (Full Track only)
Take five invented tickets and process them by hand and with a short script: lowercase, tokenize, remove one stop word list, then list the vocabulary and the word pairs.
Checked on the official page (18 Nov 2026): scikit-learn, Feature extraction: the built-in English stop-word list has known issues, and stop words can matter for some tasks.

DUnit D: Text vectorization4 ESSENTIAL · 2 OTHER

You will be able to: You can explain how a message becomes a row of numbers and why TF-IDF weights some words more than others.

IDConcept and what it meansLevelLearn firstWhere used in TicketSense-AI
D1Bag of WordsDescribing a text by how many times each vocabulary word appears; word order is ignored.EssentialC2, C5First way to count words per ticket
D2Term Frequency (TF)How often a word occurs within one ticket.EssentialD1How often a word appears in one ticket
D3Inverse Document Frequency (IDF)How rare a word is across all tickets; rarer words weigh more.EssentialD2Down-weighting words common in all tickets
D4TF-IDFTF multiplied by IDF: words frequent in one ticket but rare overall score highest.EssentialD2, D3The text representation named in the brief
D5Word embeddingsDense number vectors that capture word meaning, learned from large text collections.UsefulD1Idea only; the brief allows a pretrained model after the baseline
D6TF-IDF vs embeddingsTF-IDF counts words; embeddings capture meaning; the brief starts with TF-IDF.UsefulD4, D5Explaining why the baseline starts with TF-IDF
Learn first
Tokenization and vocabulary (C2, C5).
Why it matters
Models cannot read text; the way you turn words into numbers decides what the model can notice.
Minimum Path practice (the real project step)
Fit a TfidfVectorizer on your training split only and print the ten highest-weight words for one category (5.4).
Expected output
A short printed list of top words for one category, and a note on what surprised you.
How to verify
Say why the word "the" gets a low weight and "refund" a higher one, and when two different tickets could get the same vector.
Optional warm-up on invented data (Full Track only)
For four invented tickets, build a word-count table by hand, compute TF and IDF for two words, then check your numbers against a scikit-learn vectorizer.
Checked on the official page (18 Nov 2026): scikit-learn, Feature extraction: tf-idf = tf x idf. scikit-learn's default idf is smoothed, so it differs slightly from the textbook formula.

EUnit E: Classification algorithms3 ESSENTIAL · 3 OTHER

You will be able to: You can explain how a model learns from TF-IDF numbers and give a reason for choosing it.

IDConcept and what it meansLevelLearn firstWhere used in TicketSense-AI
E1Logistic RegressionA linear model that outputs a probability for each category (predict_proba).EssentialB3, D4Baseline named in the brief; gives the probabilities for confidence
E2Linear SVMA linear model that finds the best separating boundary. It gives scores, not probabilities, unless calibrated (I7).UsefulB3, D4Optional second model named in the brief
E3Naive BayesA fast probability-based model that treats words as independent.UsefulD1, D4A simple comparison model for text
E4Random ForestMany decision trees voting together; often weaker on sparse text.UsefulB3Contrast with linear models on sparse text
E5How they work and when to use eachMatching a model's strengths to your data, size and need for probabilities. For the confidence feature, Logistic Regression is the simplest choice.EssentialE1Justifying your final model choice to your supervisor
E6scikit-learn PipelineChains the vectorizer and the classifier so fitting happens on training data only, and the whole chain is saved as one file.EssentialD4, E1Baseline model, avoiding leakage, saving with joblib
Learn first
Classification (B3) and TF-IDF (D4).
Why it matters
You must justify why a model fits this data, not just report that it scored well.
Minimum Path practice (the real project step)
Train Logistic Regression inside a Pipeline (TF-IDF then classifier) on your training split and predict three new messages (5.4). Linear SVM only if time allows (7.2).
Expected output
A short script, three predictions, and your own one-line description of each model you considered.
How to verify
Explain how Logistic Regression and Linear SVM differ in what they output, and when you would not choose Random Forest for text.
Optional warm-up on invented data (Full Track only)
Write a one-line description for each model, then train Logistic Regression on a small invented dataset and predict three new messages.
Checked on the official page (18 Nov 2026): scikit-learn, LogisticRegression: for three or more classes it optimizes a multinomial loss (except the liblinear solver); predict_proba columns follow classes_.

FUnit F: Model evaluation8 ESSENTIAL · 1 OTHER

You will be able to: You can judge a model honestly, spot a misleading score, and explain what the numbers do and do not say.

IDConcept and what it meansLevelLearn firstWhere used in TicketSense-AI
F1Train/test splitHiding some tickets from training so testing is honest.EssentialB4, B5Keeping unseen tickets for honest testing
F2Stratified samplingSplitting so every category keeps its share in both train and test.EssentialF1Keeping category proportions in both splits
F3Cross-validationTesting on several different splits and averaging the score.UsefulF1, F2A steadier score on a small dataset
F4Accuracy, precision, recall, F1-scoreAccuracy counts all correct answers; precision and recall check each category; F1 combines them.EssentialF1Measuring each category
F5Macro, micro and weighted F1Ways to average F1 over categories: equal weight, pooled counts, or weighted by category size.EssentialF4Choosing which average suits uneven categories
F6Confusion matrixA table of true vs predicted categories showing which get confused.EssentialF4Seeing which categories get mixed up
F7Class imbalanceSome categories have far fewer tickets than others. One simple remedy to try and measure: class_weight="balanced".EssentialF2, F5Some categories have far fewer tickets
F8Data leakageTest-set information leaking into training, for example fitting the vectorizer before splitting.EssentialF1, C1Avoiding test information in training or in the vectorizer
F9Error analysisReading wrong predictions to find patterns and causes.EssentialF6Reading wrong predictions to find causes
Learn first
Overfitting and generalization (B5), a trained pipeline (E1, E6).
Why it matters
Accuracy alone can hide a weak category; leakage can make a bad model look excellent.
Minimum Path practice (the real project step)
Evaluate your Pipeline on the held-out test set: per-category precision, recall and F1, macro F1, confusion matrix; then list and group the wrong predictions (6.1 to 6.4).
Expected output
A metrics table, a confusion matrix and a short list of error groups, all from your real data.
How to verify
Explain, using one example, why 90% accuracy can be bad when one category holds 90% of tickets, and name one way data leakage could happen with TF-IDF.
Optional warm-up on invented data (Full Track only)
On a small invented dataset, split with stratification, train, print precision/recall/F1 per category, draw the confusion matrix and list every wrong prediction. These are practice numbers, not project results.
Checked on the official page (18 Nov 2026): scikit-learn, Cross-validation and Metrics: preprocessing must be learnt on training data only (a Pipeline does this); StratifiedKFold keeps class percentages; macro, micro and weighted F1 average differently; confusion-matrix rows are true classes.
